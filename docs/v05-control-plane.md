# V0.5 durable automation control plane

## Ownership and current infrastructure

GitHub holds source and the existing Pages frontend. It holds no runtime AQM secrets. Cloud Run owns the trusted API and runner; Firestore owns durable forms, policies, schedules, claims, runs, evaluation slots, and records; Secret Manager owns the separate Genesys client-credentials ID/secret and Jev key. One Cloud Scheduler job calls one authenticated tick route hourly. Browser PKCE remains separate and continues to power interactive Genesys browsing.

On 30 September 2026, `genesys-aqm-2026` was created with billing linked. Firestore Native `(default)` exists in `europe-west2` and reports free tier. The required APIs, `aqm-runtime` and `aqm-scheduler` identities, and three app-specific secrets with enabled version 1 exist. Cloud Run `aqm-api` is deployed at `https://aqm-api-bd54ukouga-nw.a.run.app`; the hourly `aqm-hourly` Scheduler job uses that URL as its OIDC audience. A live health request returned 200, unauthenticated browser/internal requests returned 401/403, and a manually triggered Scheduler tick returned 200 with no schedules. No real Genesys transcript or Jev evaluation has been proved through this server path. The browser user allowlist is empty pending verification. Local gcloud's prior active configuration belongs to Environment Builder; all AQM commands pin `--project=genesys-aqm-2026`.

## Authorization and data

The Cloud Run service is publicly reachable at the platform layer because a static Pages app cannot supply a Google service identity. Every `/api/*` request must carry a short-lived Genesys PKCE user token. The API checks that token with the fixed-region Genesys `/api/v2/users/me` endpoint and requires the returned user ID on an explicit server-side allowlist. CORS admits only `https://simonridd.github.io`; CORS itself is not authorization. `/internal/scheduler/tick` requires a Google-signed OIDC token with the configured Cloud Run URL audience and exact `aqm-scheduler` email. Health is public and contains no data. This is a small-owner V0.5 authorization model, not a multi-tenant permissions system.

No browser receives Firestore credentials, automation credentials, Jev key, or automation access token. Server records keep derived scores, form snapshot, IDs, queue/agent/topic, and provenance, not real transcript messages. Transcripts are held in memory for evaluation. A reserved evaluation slot is marked before Jev is called. If the call or persistence outcome is ambiguous, the slot remains `started`; an operator must reconcile it before any retry can charge Jev again. A completed slot and its record are written together in a Firestore transaction. Run claims are transactional and scoped to policy version plus period, covering manual and scheduled overlap. Incomplete claims can be recovered after their lease expires. Scheduled partial/failed runs advance the schedule to avoid an hourly paid retry loop; their failures remain visible.

Browser-local V0.4 forms, policies, runs, and evaluation records remain in localStorage and are explicitly separate from server history. The Policies page can deliberately publish local forms/policies to the server. It never migrates browser history silently. The local reset and history clear controls do not affect Firestore.

## Remaining setup

1. Confirm the separate Genesys Cloud **Client Credentials** OAuth client has the Analytics, queue lookup, recording, and Speech and Text Analytics permissions needed for the monitored divisions. This is separate from the existing browser PKCE client. The three secret values were added by the user directly in Secret Manager; their contents were never read by the repository tooling. Secret Manager console: `https://console.cloud.google.com/security/secret-manager?project=genesys-aqm-2026`.
2. In AQM Settings, sign in with browser PKCE and press **Verify connection** to see the actual Genesys user ID. Set `AQM_ALLOWED_GENESYS_USER_IDS` to that verified ID and rerun `scripts/deploy-gcp.sh`. Until then, the API denies all browser routes. The script pins initial secret version 1; rotate by deploying a reviewed new version reference.
3. Set the public `VITE_AQM_API_ORIGIN` to the deployed Cloud Run URL for the Pages build, verify server auth and manual plan → preview → confirm → execution with real eligible interactions, then enable daily/weekly schedules. Do not infer live transcript or Jev proof from local tests.

A Cloud Run service's platform-level unauthenticated invoker permission exists only to let Pages reach the in-app Genesys authorization boundary. The API fails closed if the Genesys allowlist is empty. The Scheduler route does not accept browser bearer tokens. Keep a bounded number of trusted Genesys user IDs in the allowlist.
