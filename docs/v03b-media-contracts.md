# V0.3B Genesys media contracts

A real Ireland-region voice example (screenshots supplied by Simon on 29 September 2026) established that the Speech and Text Analytics `communicationId` comes from a **customer participant's voice session**. The previous implementation picked the first session across all participants, which can be an agent session. The example also returned a signed `api-downloads.mypurecloud.ie/transcriptsCache/…` URL rather than an AWS hostname visible to the browser. These observations are about voice and must not be projected onto other channels.

| Genesys media type | Communication identity | Transcript transport and raw payload | V0.3B state |
| --- | --- | --- | --- |
| `voice` | Distinct, valid `sessionId` values under customer/external participant voice sessions (up to 10) | [Speech and Text Analytics transcript URL](https://github.com/MyPureCloud/platform-client-sdk-javascript/blob/master/build/docs/SpeechTextAnalyticsApi.md), then HTTPS signed download. `transcripts[].phrases[]` supplies `participantPurpose`, `startTimeMs`, and `text`/`decoratedText`. | Implemented; browser delivery still awaits a live AQM check. |
| `message` | Customer/external message session IDs | A separate digital-message contract. The [official Conversations API](https://github.com/MyPureCloud/platform-client-sdk-javascript/blob/master/build/docs/ConversationsApi.md) lists message conversation and message retrieval endpoints; payload mapping needs a real representative example. | Explicitly unsupported in this tranche; no voice endpoint call. |
| `chat` | Customer/external chat session IDs | A separate chat contract. No transcript endpoint or payload mapping has been validated for the AQM use case. | Explicitly unsupported in this tranche; no voice endpoint call. |
| `email` | Customer/external email session IDs | A separate email contract. The [official Conversations API](https://github.com/MyPureCloud/platform-client-sdk-javascript/blob/master/build/docs/ConversationsApi.md) lists email conversation and message retrieval endpoints; payload mapping needs a real representative example. | Explicitly unsupported in this tranche; no voice endpoint call. |
| Other/unknown | None | No assumed transcript format. | Unsupported. |

`src/domain/genesysMedia.ts` defines the discriminated media contract and selects customer communication IDs. `src/domain/sources.ts` implements only the voice transport. `src/domain/genesys.ts` normalizes only validated voice phrases into the existing provider-neutral `Conversation.messages` shape. Synthetic conversations retain their original format and source. Message, chat, and email remain discoverable as interactions but show an **Unsupported** transcript status instead of a misleading voice-transcript failure; they cannot enter a paid evaluation without textual content.

For Ireland voice downloads, the allowlist now includes the exact observed `https://api-downloads.mypurecloud.ie` origin with `/transcriptsCache/` path, alongside the existing AWS/CloudFront signed-host allowance. It does not accept arbitrary user-entered hosts. The application sends no Genesys bearer token to the signed download URL, limits the accepted transcript size, validates the voice payload shape, and never stores or displays the signed URL. An unavailable transcript and a retrieval error are reported separately. The credential-free dummy-path CORS probe returned `Access-Control-Allow-Origin: *`; **a real AQM browser download is still needed** to establish transcript proof level E.

No real transcript text or signed URL from the screenshots was copied into fixtures or repository files. Test fixtures are fictional.
